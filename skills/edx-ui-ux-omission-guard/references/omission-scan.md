# 遗漏扫描

对本次改动会碰到的表面逐条判断。不适用就跳过。命中后只标一类。

- 必须收口：不做就会让用户点名的交互失败，或这次 diff 直接引入。先改完。
- 候选询问：真实但用户没要求。不改代码，留给文末提问。

| 类 | 看什么 | 默认处置 |
|---|---|---|
| 未保存离开 | 路由、返回、刷新、关层时 dirty 是否丢失且无提示 | 编辑流里必须收口；只加文案提示，不加新视觉组件 |
| 失败后的输入 | 保存失败是否还留着用户输入 | 必须收口 |
| 关层时机 | 请求未成功就关 Drawer / modal | 必须收口 |
| 旧响应覆盖 | 快切 Tab、快改筛选、连点保存 | 必须收口，只用序号 |
| 焦点归还 | 弹层关闭后焦点是否回到触发控件；弹层内焦点是否被裁切 | 这次新增或改弹层则必须收口 |
| 键盘路径 | 新控件能否 Tab 到达、Enter/Esc 是否和现有约定一致 | 改了热区或弹层则必须收口 |
| 热区与遮挡 | 图标按钮小于约 24px、被 overlay 盖住、pointer-events 穿透 | 必须收口 |
| 滚动锁 | 弹层打开后背景仍滚，或关闭后页面滚不动 | 这次改覆盖层则必须收口 |
| 键盘顶起 | 移动端键盘挡住正在编辑的字段，且没有滚动到可见 | 候选询问，除非用户在修这个字段 |
| 只靠颜色 | 错误、必填只靠红色，无文字 | 编辑校验必须有文字；其余候选询问 |
| 禁用无原因 | 按钮 disabled 但界面不说明为什么 | 候选询问 |
| 破坏性动作 | 删除、覆盖、离开丢数据没有既有确认或可撤销 | 候选询问，不私自加确认框 |
| 部分成功 | 多字段保存只成功一半，界面像全成功 | 接口已表达部分失败则必须收口，否则候选询问 |
| 列表不同步 | 详情保存成功，打开它的列表仍是旧值 | 用户要求保存后刷新则必须收口，否则候选询问 |
| 并发覆盖 | 两人编辑同一条，后写覆盖先写且无提示 | 候选询问 |
| 空与权限 | 无数据、无权限看起来像保存成功或白屏 | 写路径导致的误成功必须收口；读路径交给 async-state-completeness |
| 长文与窄屏 | 标签、错误、按钮文字把布局撑破或被裁 | 必须收口 |
| 动态插入跳动 | 错误文案或异步块出现时把焦点控件顶出视口 | 这次会插入内容则必须收口 |
| 动效 | 新动画没有尊重 reduced-motion | 候选询问，除非本次正在加动画 |

## 提问

必须收口改完后先写交互建议，再写「要不要补这些交互」。扫描表只是种子。

交互建议按当前界面分成三组，每组都要有：

- **A 强相关**：这次 diff 或同一控件的下一步。至少 2 条。例如刚接上保存，就写脏数据离开、失败后输入还在不在。
- **B 弱相关**：同一页面，但不是这次改动的必经路径。至少 2 条。例如列表行没有刷新、禁用按钮没有原因。
- **C 其他补充建议**：相邻流程或整页一致性。至少 1 条。例如键盘把字段顶出屏幕、删除没有可撤销。

「要不要补这些交互」从这些建议展开，至少 5 条。编号与建议相同：`A1`、`B1`、`C1`。每条写清触发动作、现在会怎样、补上后会怎样、不会改什么。问用户要哪些编号。未回复前不实现。

不足 5 条，或某一组为空，就继续从当前组件推断，不要用空泛句充数，也不要把弱相关抬进 A。询问段超过 8 条时先砍 C，再砍 B。不要假装没有未知。
