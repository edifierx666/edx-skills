# 编辑闭环契约

五段都要达到最低标准，少一段就不算完成。

1. 展示当前值，并区分服务端原值与本地编辑态。
2. 输入改变本地状态，有 dirty 或等价标记。需要时有取消、重置、未保存提示。
3. 提交前校验，用户能看见错误。规则靠近边界，不散落在多个回调里。
4. 触发点明确。payload 由 builder / adapter 组装。禁止猜测式多源赋值，禁止把视图状态原样当 payload。
5. 成功和失败都有可见反馈。成功后重置 dirty，并刷新详情/列表或更新 canonical state。只有成功后才关弹层。更新前确认组件仍在，且通过时序校验。

防竞态：局部自增 `reqId`，回调第一行不匹配就返回。不强制 AbortController。不擅自加 loading 遮罩或 disabled；已有 loading 才复用。

接口未给时提供 `handleSave` 和时序占位，并用 `// TODO: 接入真实的保存接口` 标出接入点。

即时提交失败要回滚或恢复。只弹提示、不同步状态，不算闭环。
