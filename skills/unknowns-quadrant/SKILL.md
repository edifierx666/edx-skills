# 盲区四象限（Unknowns Quadrant）

## 这个 skill 做什么、不做什么

**做**：对用户给定的任务、模块或领域做真实调查，产出一张四象限盲区地图——每条盲区带证据，讲清「你可能以为什么、实际是什么」。

**不做**：不给行动建议，不教用户怎么写 prompt，不替用户做任何取舍。地图交出去，怎么走由用户决定。报告里出现「你应该」「建议你」「prompt 里要写」这类句子即违规——唯一例外是②象限里罗列决策选项的客观后果，那是信息，不是建议。

## 四象限模型

模型由两条轴构成，判定任何一条信息缺口时先过这两条轴：

- **觉察轴**：你是否意识到这个缺口的存在？
- **掌握轴**：答案是否已经在你脑中？

|  | 答案在你脑中 | 答案不在你脑中 |
| --- | --- | --- |
| **意识到** | ① 已知的已知 | ② 已知的未知 |
| **没意识到** | ③ 未知的已知 | ④ 未知的未知 |

四个象限的本质区别不是「重要程度」，而是**答案在哪里、靠什么操作消除**。混淆象限会用错操作——这是本模型存在的全部意义。

### ① 已知的已知：你说得出、也确信的

- **体感**：这就是你在任务描述里已经写下的部分
- **答案在哪**：你脑中，且已用语言表达出来
- **陷阱**：伪已知。①是四个象限里唯一「不算缺口」的，因此也最会骗人——你确信的事实可能过时、可能从来就错。它比④更危险的地方在于：④至少还会让人警觉，①披着「已确认」的外衣直接进入决策
- **消除操作**：复核——对着疆域抽查验证，而不是照单全收

### ② 已知的未知：你说得出「我不知道 X」的

- **体感**：待办清单上的问号；「还没定」「到时候再说」「你看着办」
- **答案在哪**：两种截然不同的位置，必须分开——**在疆域里**（查证可得，是调查任务）或**在你手里**（等你拍板，是决策任务）
- **陷阱**：拖延。知道有坑，想着「做的时候再说」，结果坑在架构层，返工成本翻倍
- **消除操作**：查证，或拍板

### ③ 未知的已知：你说不出、但看到就能认出的

- **体感**：「不是这个感觉」「对，就是这样」——描述不出来，但判断力真实存在。品味、取舍、审美都住在这里
- **答案在哪**：你脑中，但以直觉形式存在，语言直接取不出来
- **陷阱**：错把它当②处理——逼自己用文字描述品味。描述必然失真，得到的东西「完全符合描述，但就是不对」
- **消除操作**：呈现——给出多个差异足够大的具体实物（原型、方向、参照），让判断力直接工作，跳过语言

### ④ 未知的未知：你连问题都提不出来的

- **体感**：没有体感——这正是它的定义。事后的体感是「我怎么会没想到」
- **答案在哪**：只在疆域里。你脑中既没有答案，也没有问题
- **陷阱**：最贵。它不在规划时暴露，只在实现中段或上线后爆炸；且规划做得越细，越容易产生「已经想全了」的错觉
- **消除操作**：勘探——由查过疆域的一方主动告诉你。这是四种操作里唯一不能由你自己发起的，也是本 skill 的核心工作

### 判定试金石

拿到一条信息缺口，按顺序问：

1. 用户已经说出来了？→ ①（进复核队列，不是照抄队列）
2. 用户能说出「我不知道 X」？→ ②（再分：查证可得 / 只能拍板）
3. 用户说不出，但给他看实物就能挑？→ ③
4. 用户连问题本身都提不出来？→ ④

常见误判：把「懒得问」当④（其实是②，用户知道没想清）；把品味硬套成决策点（③给文字选项挑不出来，必须给实物）；把用户的原话当①直接采信（不复核就是在传播伪已知）。

## 工作流程

### 1. 锁定范围

弄清两件事即可开扫：任务/领域是什么、用户对它的熟悉程度。缺哪个问哪个，一次只问一个。

### 2. 调查疆域

③④象限的质量完全来自这一步，①的复核也依赖它。禁止只凭文件名、目录结构或行业常识下结论。

代码库任务——先回答「完成这个任务要动哪几处」，以此圈定范围，然后：

- 读入口与调用链的真实代码
- 读项目内已有的同类实现——最容易暴露「必须遵守的隐性约定」
- 读相邻测试的断言——「正确」的最硬定义
- 看相关目录 git log 的 fix / revert——前人踩过的坑
- 查配置、env、feature flag——环境差异型盲区的高发区

领域任务（视频、设计、法律文书等）——结合自身知识，拿不准就搜索：

- 该领域的标准工作流，用户的任务处在哪一环
- 内行判断好坏的质量维度（常直接产出③）
- 新手最常犯、且自己看不出来的错（常直接产出④）

### 3. 分拣与成文

每条发现过一遍试金石入象限。合格线：

- **④**必须写成「你可能以为 → 实际是（证据）→ 不知道的后果」三段，缺证据不成文
- **③**必须写清「你会在哪个时刻遇到这个判断」和「到时候会看到哪些差异」，不许只写「风格需要确认」
- **②**查证可得的当场给答案（这是扫描的直接价值）；只能拍板的列选项与各自客观后果，不给推荐
- **①**给出复核结论：确认为真的一笔带过，复核有疑的重点展开

宁缺毋滥。某象限没有实质发现就写「本次未发现」；全盘扫完确认用户理解已够动手，就直说「没有实质盲区」——这是合格结论，不是失败。

## 报告格式

固定结构。④在最前，因为它是用户唯一无法自查的象限；①在最后，因为它主要是核对。表格只做索引，理解靠正文——禁止把内容塞进表格单元格。

````markdown
# 盲区四象限：<任务/领域名>

> 扫描范围：<一句话> ｜ 最重要的发现：<一句话>

## 矩阵总览

|  | 答案在你脑中 | 答案不在你脑中 |
| --- | --- | --- |
| **意识到** | ① 已知的已知 · N 条（复核有疑 M 条） | ② 已知的未知 · N 条 |
| **没意识到** | ③ 未知的已知 · N 条 | ④ 未知的未知 · N 条 |

## ④ 未知的未知 —— 你连问题都提不出来的

### ④-1 <盲区标题>
- **你可能以为**：<不熟悉的人的自然假设>
- **实际是**：<疆域里的真实情况>（`file:line` 或出处）
- **不知道的后果**：<会在哪一步、以什么形式爆炸>

## ③ 未知的已知 —— 看到才认得出的

### ③-1 <判断点标题>
- **它是什么**：<为什么这是品味/取舍，语言为何取不出来>
- **你会在哪遇到它**：<任务的哪个环节会撞上这个判断>
- **到时候的差异长什么样**：<几个方向的具体分野>

## ② 已知的未知 —— 你自己也知道没想清的

**查证可得（已替你查了）**
- <问题> → <答案>（证据）

**只能你拍板的**
| 决策点 | 选项 | 各自后果 |
| --- | --- | --- |

## ① 已知的已知 —— 复核结果

- ✅ 确认为真：<一行一条>
- ⚠️ 复核有疑：你的理解是 <X>，疆域里是 <Y>（证据）

## 未扫区域

<哪些没查、为什么>
````

报告较长时全文落盘 `.__docs`，聊天中保留矩阵总览 + ④全量 + 其余摘要。

## 红线

- **无证据不成文**：代码库结论必须来自实际读过的代码；推测必须标「❓ 推测」并给验证路径
- **不给建议**：不出现「建议」「应该」「推荐」「prompt 里要写」；②的选项后果照实陈述，倾向性词汇一律不用
- **不凑数**：空象限直说「本次未发现」
- **只读**：只扫描和解释，不修改文件（`.__docs` 落盘报告除外）
