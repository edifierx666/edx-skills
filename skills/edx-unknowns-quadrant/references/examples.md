## 场景 2：不熟悉的技术栈

**用户**：「我要给视频调色，但我不知道什么是调色。」

**调查**：
- 搜索 color grading、video processing 相关文档、教程
- 查找项目中是否已有视频处理相关代码
- 检查依赖库（如 ffmpeg、WebGL 库、canvas API）
- 查看浏览器兼容性和性能限制

### I. 已知的已知

#### 需求点：给视频调色
- **用户表达**：需要给视频调色
- **这是什么**：调色（Color Grading）是调整视频的色彩表现，让画面更有质感、符合特定风格（如电影感、复古感、清新感）。本质上是修改每个像素的 RGB 值
- **技术含义**：需要「视频帧提取 → 像素级色彩变换（亮度/对比度/饱和度/色温/色调曲线）→ 实时预览 → 导出渲染」
- **涉及模块**：
  - 视频解码：把视频文件拆成一帧帧图像
  - 色彩处理引擎：可以用 Canvas 2D API、WebGL Shader、FFmpeg WASM
  - UI 控制界面：滑块、色轮、预设滤镜按钮
  - 导出模块：把处理后的帧重新编码成视频文件
- **工作原理**：用户上传视频 → 提取每一帧到 canvas → 用户拖动"亮度"滑块 → Shader 实时计算新的像素值 → canvas 刷新显示 → 用户满意后点击导出 → 逐帧处理并编码成视频
- **需确认**：调色是实时的还是离线的？需要支持哪些视频格式（MP4/MOV/WebM）？是否需要预设滤镜？是否需要保存调色参数以便复用？

### II. 已知的未知

#### 核心疑问 · 调色的技术实现路径
- **问题**：不确定应该用 WebGL Shader、Canvas 2D API 还是 FFmpeg WASM
- **影响**：直接决定性能、浏览器兼容性和开发复杂度
- **证据**：项目已引入 three.js（package.json v0.152.0），可用于 WebGL，但未找到 FFmpeg WASM
- **待确认**：需要实时预览还是离线处理？对性能要求多高？

#### 核心疑问 · 色彩参数配置
- **问题**：不确定调色需要支持哪些参数（亮度、对比度、饱和度、色温、色调曲线等）
- **影响**：决定 UI 控制界面的复杂度和调色效果的专业程度
- **证据**：未找到设计稿或需求文档
- **待确认**：用户期望的调色专业度？是简单滤镜还是专业调色台？

#### 待确认细节 · UI 交互设计
- **问题**：不确定调色界面应该用滑块、色轮还是预设滤镜按钮

- **证据**：团队有统一的滑块组件 `<Slider>`（src/components/Slider）

### III. 未知的已知

**与你的假设可能冲突的事实 · WebGL 着色器需要手动管理 GLSL**
- **你可能以为**：three.js 内置了常见的调色效果
- **实际上**：three.js 只负责 WebGL 渲染管线，具体的调色效果需要自己写 GLSL 着色器代码
- **位置**：three.js 官方文档 shaders 部分
- **影响**：开发复杂度远高于预期，需要学习 GLSL 语法

**可以直接利用的现有资源 · VideoPlayer / Slider 组件**
- **资源**：已有 `VideoPlayer` 组件（src/components/VideoPlayer.tsx）支持帧提取和 canvas 渲染；团队有统一滑块组件 `<Slider>`（src/components/Slider）
- **用途**：VideoPlayer 用于帧提取和实时预览；Slider 用于亮度、对比度等参数的实时控制
- **注意**：需先确认支持的视频格式

**团队约定与规范 · 色彩处理使用线性空间**
- **规范**：团队约定在 shader 中使用线性 RGB 空间进行计算，显示前转 sRGB
- **来源**：src/lib/color/README.md
- **违反后果**：颜色偏差，特别是阴影和高光区域

### IV. 未知的未知

**与你的假设可能冲突的事实 · 色彩空间转换会影响最终效果**
- **你可能以为**：直接修改 RGB 值就行
- **实际上**：色彩空间转换（sRGB vs Linear RGB）会影响最终效果，需要在 shader 中显式转换，否则会出现颜色偏差
- **证据**：WebGL 规范、three.js 文档中的色彩管理章节
- **风险**：调色后的视频颜色不准确，特别是阴影和高光区域
- **触发条件**：使用 WebGL Shader 进行色彩计算时

**你没考虑过的场景 · 4K 视频需要降采样**
- **场景**：用户上传 4K 视频（3840x2160）进行调色
- **发现**：浏览器性能限制，4K 视频实时调色会掉帧，需要降采样到 1080p 预览，导出时再用原始分辨率
- **证据**：WebGL 最大纹理尺寸限制、性能测试数据
- **影响**：需要实现预览/导出双流程，增加复杂度
- **触发条件**：视频分辨率 > 1920x1080

**你没考虑过的场景 · 移动端 WebGL 支持有限**
- **场景**：用户在 iOS Safari 上使用调色功能
- **发现**：iOS Safari 对 canvas 尺寸有限制（最大 4096x4096），超出会渲染失败
- **证据**：iOS Safari 文档、已知兼容性问题
- **影响**：移动端无法处理高分辨率视频
- **触发条件**：iOS Safari + 视频尺寸 > 4096

**隐藏风险 · 品牌色彩规范约束**
- **风险**：调色预设需要符合品牌色彩规范，设计团队有 LUT（Look-Up Table）文件可以直接导入
- **证据**：设计团队共享文件夹中的 brand-color-lut.cube 文件
- **影响**：如果不使用品牌 LUT，调色效果可能与品牌调性不符
- **触发条件**：产品上线后设计团队 review

## 场景 3：认证模块重构

**用户**：「我在给项目加一个新的认证提供商，但对 auth 模块一无所知。」

- 查找相关测试用例、错误日志

### I. 已知的已知

#### 需求点：支持新的认证提供商
- **用户表达**：给项目加一个新的认证提供商（如 Google、GitHub）
- **这是什么**：认证提供商是第三方登录服务，让用户不用记住你网站的密码，直接用 Google/GitHub 账号登录。本质上是"借用"大厂的账号体系
- **技术含义**：需要「OAuth2 授权码流程 + 跳转回调处理 + Access Token 存储 + 用户信息映射 + 会话管理」
- **涉及模块**：
  - `src/lib/auth/provider.ts`：定义 AuthProvider 抽象接口，每个提供商实现这个接口
  - `src/pages/api/auth/callback.ts`：处理第三方登录跳转回来的回调请求
  - `src/lib/auth/session.ts`：管理用户登录状态（session/JWT）
  - `src/lib/auth/token-refresh.ts`：当 token 过期时自动刷新
- **工作原理**：
  1. 用户点击"用 Google 登录" → 跳转到 Google 授权页面
  2. 用户同意授权 → Google 跳转回你的网站（带 authorization code）
  3. 后端用 code 向 Google 换取 access token
  4. 用 access token 向 Google 请求用户信息（邮箱、头像等）
  5. 在数据库中创建或关联用户记录
  6. 生成自己的 session/JWT，让用户保持登录状态
- **需确认**：
  - 新提供商的回调域名是什么？（需要在提供商后台配置白名单）
  - 是否需要本地注册？（第三方登录是自动创建账号，还是必须先有本地账号才能绑定？）
  - 是否需要第三方 cookie？（Safari 会阻止第三方 cookie）

### III. 未知的已知

**与你的假设可能冲突的事实 · 并发登录 session 覆盖**
- **你可能以为**：每个用户登录有自己独立的 session
- **实际上**：并发登录时 session 会互相覆盖，导致用户 A 登录时用户 B 被踢出
- **位置**：src/lib/auth/session.ts L45-67
- **影响**：如果两个用户在同一设备上同时登录，后登录的用户会覆盖先登录的 session

**可以直接利用的现有资源 · AuthProvider 抽象接口 / Token 刷新中间件**
- **资源**：已有 `AuthProvider` 抽象接口（src/lib/auth/provider.ts）支持多种提供商热插拔；已有 token 刷新中间件（src/lib/auth/token-refresh.ts）基于 refresh token + HTTP-only cookie
- **用途**：新提供商只需实现接口的 authorize()、callback()、getUserInfo() 三个方法；无需自己实现 token 刷新
- **注意**：需确保新提供商支持 refresh token 机制

**团队约定与规范 · SSR 需要环境变量配置**

- **来源**：src/app/api/auth/[...nextauth]/route.ts
- **违反后果**：SSR 环境下认证流程无法正常工作
