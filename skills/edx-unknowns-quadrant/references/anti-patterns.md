## ❌ 虚构盲区（最严重）

```markdown
### 与你的假设可能冲突的事实

#### 并发登录 session 覆盖
- **你可能以为**：每个用户有自己的 session
- **实际上**：项目使用共享 session，并发会覆盖
- **位置**：src/lib/auth/session.ts L45
```
（如果未实际查看 src/lib/auth/session.ts，这就是虚构）

**正确做法**：先真实调查，再区分「已确认」与「未能确认」。

```markdown
### 调查结果

经调查以下关键词：`session`、`auth`、`login`、`concurrent`

**已确认的事实**：
- 项目使用 `next-auth` 进行认证（package.json L23）
- Session 存储在 JWT token 中（src/pages/api/auth/[...nextauth].ts L12-18）

**未能确认的部分**：
- 并发登录是否有覆盖问题（未找到相关测试或 issue）
- Session 管理的详细实现（next-auth 内部机制）
```

## ❌ 对「已知的已知」一笔带过

```markdown
## I. 已知的已知

- 需要做一个用户列表
- 支持分页
```

**问题**：没有展开技术含义，用户可能对背后的技术环节完全不了解。

**正确做法**：

```markdown
## I. 已知的已知

#### 需求点：用户列表展示
- **用户表达**：需要做一个用户列表
- **这是什么**：在网页上显示一个表格，每一行代表一个用户，包含用户名、邮箱、角色等基本信息
- **技术含义**：需要「GET 接口调用（从服务器拿数据）+ 表格组件（把数据变成可视化行列）+ 数据映射（后端字段对应表格列）+ 加载状态 + 空态处理 + 错误处理」
- **涉及模块**：
  - src/pages/UserList.tsx：页面入口，协调各个组件
  - src/api/user.ts：封装接口调用，统一错误处理
  - src/components/Table：通用表格组件
- **工作原理**：用户打开页面 → 调用 GET /api/users → 接口返回数据 → 表格逐行渲染
- **需确认**：是否需要实时刷新？是否需要导出功能？
```

## ❌ 空想未知

```markdown
## IV. 未知的未知

#### 性能问题
- **发现**：大数据量可能导致性能问题
- **证据**：一般来说，列表数据多了会卡
```

**问题**：没有真实调查，只是泛泛而谈。

**正确做法**：搜索现有列表组件，检查是否有虚拟滚动、分页加载；查看 issue 中是否有性能投诉。

```markdown
## IV. 未知的未知

**隐藏风险 · 虚拟滚动缺失导致大列表卡顿**
- **发现**：现有 `<Table>` 组件未实现虚拟滚动，在 1000+ 行数据时会出现明显卡顿
- **证据**：src/components/Table/index.tsx L45-67 使用普通 map 渲染；GitHub issue #3421 报告了订单列表卡顿问题
- **风险**：如果用户列表超过 500 条，滚动会有明显延迟
- **触发条件**：管理员查看全量用户列表、导出前预览数据
```

## ❌ 未按认知距离分组

```markdown
## IV. 未知的未知

- 代码中有 TODO 注释
- HTTPS 证书可能过期
- 移动端适配问题
- 变量命名不规范
- 数据库索引未优化
```

**问题**：把「与假设冲突」「未考虑场景」「隐藏风险」揉成一个扁平列表，用户无法快速定位最需要关注的项。本 skill **只按认知距离分组，不按严重度分级**（不要用「1/2/3 级」这类标签）。

**正确做法**：按认知距离分三组，最需要颠覆认知的「与假设冲突」放最前。

```markdown
## IV. 未知的未知

### 与你的假设可能冲突的事实

#### HTTPS 证书即将过期
- **你可能以为**：证书由运维自动续期，不用关心
- **实际上**：生产环境证书将于 30 天后过期（2026-08-06），未配置自动续期
- **证据**：.env.production 中证书路径 /etc/ssl/cert.pem，openssl 验证有效期
- **风险**：证书过期后所有 HTTPS 请求被浏览器阻止，服务完全不可用
- **触发条件**：2026-08-06 后任何用户访问

### 你没考虑过的场景

#### 移动端适配缺失
- **场景**：用户通过手机访问用户列表页
- **发现**：当前页面未做响应式适配，表格宽度固定 1200px
- **证据**：src/pages/UserList.tsx 未使用媒体查询
- **影响**：移动端出现横向滚动，内容被裁切
- **触发条件**：视口宽度 < 1200px

### 隐藏的技术风险

#### 变量命名不一致
- **风险**：部分文件用 camelCase，部分用 snake_case，降低可维护性
- **证据**：src/utils/format.ts 中函数命名混合使用
- **影响**：团队协作、code review 时产生困扰（不影响功能）
- **触发条件**：新人接手、跨模块复用工具函数时
```
